# Our Table

A shared recipe book for two: save recipes, explore nutrition, and plan meals with individual portions.

## Features

- Recipe creation, editing, search, favourites and photo uploads.
- Nutritional analysis using USDA FoodData Central and custom food labels.
- Multi-day meal planning with individual portions and ingredient aggregation.
- Step-by-step cooking mode, ingredient checklists and timers.
- Shared household recipes and meal plans with Supabase authentication.
- Recipe importing from supported websites and AI-assisted recipe drafting.

## Tech stack

Next.js App Router, React, strict TypeScript, Tailwind CSS, Radix UI, Supabase, USDA FoodData Central and the OpenAI Responses API.

## Project structure

- `src/app/`: application pages, layouts and API routes.
- `src/components/`: interface components, recipe editor and nutrition tools.
- `src/features/`: application state and local demo functionality.
- `src/lib/`: validation, Supabase clients and shared utilities.
- `src/services/`: nutrition, meal planning, importing, USDA and AI integrations.
- `src/types/`: shared domain types.
- `supabase/migrations/`: database schema, functions and RLS policies.
- `tests/`: unit, component, integration and browser tests.
- `docs/`: architecture, deployment, testing and case study documentation.

## Local development

Requires Node.js 24.15+ or 26+ (Node 22.22.2+ is also supported) and npm.

```bash
npm ci
```

Copy `.env.example` to `.env.local`, set `NEXT_PUBLIC_DEMO_MODE=true`, and run:

```bash
npm run dev
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000).

Demo mode uses browser-local fictional data without authentication or cloud persistence. Configure Supabase to enable shared household functionality.

The application has not yet been deployed. Live database migrations, authentication, storage permissions and external provider integrations require staging verification.

## Limitations

Recipe imports require accessible Schema.org JSON-LD pages. Imported recipes and AI-generated drafts require review before saving. Nutritional data is not generated by AI, and meal storage guidance is user-provided rather than independently certified.

Demo data is browser-local. Cloud edits use last-successful-save behaviour; offline synchronisation, conflict resolution and version history are future work.
